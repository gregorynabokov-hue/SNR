# Прокси для ИИ-вступлений (Cloudflare Worker)

Для деплоя с ноутбука используйте `CHECKLIST.md`: там пошаговые команды и готовый `wrangler.toml`.

Нужен один раз. Ключ OpenAI не попадает в браузер, он хранится в секретах Cloudflare.

1. Зарегистрируйтесь на cloudflare.com (бесплатный тариф подходит).
2. Установите Wrangler: `npm i -g wrangler`, затем `wrangler login`.
3. В папке `proxy/` создайте `wrangler.toml`:
   ```toml
   name = "snr-os-scenario"
   main = "worker.js"
   compatibility_date = "2024-09-01"
   [vars]
   ALLOWED_ORIGIN = "https://<user>.github.io"
   LLM_BASE_URL = "https://coarena.ai/api/v1"
   LLM_MODEL = "<название модели из списка Coarena>"
   ```
   Если `LLM_BASE_URL` не задан, прокси обращается к OpenAI. Любой OpenAI-совместимый сервис подключается так же: меняется только адрес и модель.
   `ALLOWED_ORIGIN` — адрес вашего сайта без пути. Запросы с других сайтов будут отклоняться.
4. Задайте ключ как секрет (он не сохраняется в файлах и не попадает в репозиторий). Переменная называется `OPENAI_API_KEY` независимо от сервиса:
   `wrangler secret put OPENAI_API_KEY`
   Ключ, который уже показывался в переписке или на скриншоте, нужно отозвать и создать новый.
5. Деплой: `wrangler deploy`. Получите адрес вида `https://snr-os-scenario.<name>.workers.dev`.
6. В приложении: Настройки → «Адрес сервера сценариев» → вставьте этот адрес.

Название модели берите из списка моделей выбранного сервиса: оно меняется, поэтому не копируйте его из старых инструкций.
Перед публичным пилотом проверьте условия хранения данных у сервиса-посредника. В запрос уходит только сводка без имени и сырых пульсовых данных.

Что отправляется в модель: тип протокола, номер дня, четыре значения уязвимости, краткая история последних пяти сессий (изменение пульса, дискомфорт, уровень). Имени, сырых пульсовых рядов и идентификаторов нет.

Лимиты: Worker не ограничивает число запросов на пользователя. Перед публичным пилотом добавьте ограничение (Cloudflare Rate Limiting) и бюджет в кабинете OpenAI.
